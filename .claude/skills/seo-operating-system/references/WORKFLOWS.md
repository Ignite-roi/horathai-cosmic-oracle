# SEO OS workflows

## New website onboarding
1. Inventory site/routes/CMS/DB
2. GSC + analytics baseline
3. Raw HTML technical audit
4. Business Facts extraction
5. Keyword Ownership map
6. Competitor cluster research
7. Priority scoring
8. Money-page decisions
9. Conversion instrumentation design
10. Technical fixes
11. QA/build-output gate
12. Publish
13. 7–14 day cooldown
14. Measure and prioritize next action

## Existing site with traffic
1. Protect current ranked/converting URLs
2. Pull 28/90 day query + page data
3. Find positions 4–20 and high-impression low-CTR pages
4. Detect cannibalization
5. Fix technical ownership/index issues first
6. Optimize existing owner pages before new content
7. Only then consider justified new money/support pages

## Dynamic blog/CMS publishing
1. Draft generated
2. Business-fact grounding
3. Ownership + intent collision check
4. Deterministic quality checks
5. One targeted repair maximum
6. SEO_PENDING until prerender/artifact exists
7. Sitemap inclusion from same source
8. Approval
9. Publish
10. Monitor

## SEO monitoring cycle
Weekly:
- meaningful ranking movement
- CTR opportunities
- index anomalies
- cannibalization
- revenue/lead changes

Monthly/quarterly:
- content decay
- pruning/consolidation
- business-fact revalidation
- competitor gap refresh
- link/evidence growth
- page/template quality

## Change safety
Before editing a ranked page:
- capture current title/H1/body/canonical
- capture GSC baseline
- log proposed change and reason

After deployment:
- record release/commit
- freeze major SEO edits 7–14 days
- compare against equivalent settled period
- rollback if materially worse and cause is plausible
